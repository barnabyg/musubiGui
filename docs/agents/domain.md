# Domain docs

## Before exploring the codebase

Use the single-context layout:

- Read `GLOSSARY.md` at the repository root, when present.
- Read decisions in `docs/adr/` relevant to the area being explored, when present.

If these files do not exist, proceed silently. The domain-modeling skill creates them lazily when terms or decisions are resolved.

## Use the glossary vocabulary

Use glossary terms for domain concepts in issue titles, proposals, hypotheses, and test names. If a concept is missing, reconsider whether it belongs in the project vocabulary or record the gap for domain-modeling.

## Surface ADR conflicts

When a proposal contradicts an existing ADR, identify the ADR and explain why its decision should be reconsidered.
